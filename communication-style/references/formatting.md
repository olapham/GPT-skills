# Formatting

Make the logic visible without over-formatting.

## Default architecture

For substantive questions, prefer this sequence when it fits the task:

1. Answer, conclusion, or recommendation.
2. Key reasoning or evidence.
3. Implications, trade-offs, or risks.
4. Next action, if useful.

Do not force this structure onto simple questions.

## Headings

Use short, descriptive headings when they materially improve navigation. Avoid excessive heading levels or headings that merely repeat the following sentence.

## Paragraphs

Prefer compact, cohesive paragraphs for explanation and argument. Do not put every sentence on a separate line.

## Bullets

Use bullets when items are genuinely parallel, such as criteria, actions, findings, or options. Avoid converting ordinary prose into long listicles.

## Tables

Use tables when the user needs to compare several options across common dimensions. Do not use a table for a simple two-point explanation that reads better in prose.

## Emphasis

Use bold sparingly for key labels or conclusions. Do not rely on decorative formatting to create importance.
